# Build Your Foundry

**You already have a philosophy. It's trapped in stories you haven't
written down yet.**

This is the starter kit for building your own *Foundry* — a personal
system for turning your lived expertise into something reusable,
teachable, and evolving. It accompanies the **Build Your Foundry**
workshop by Lauren Irving, but everything here works self-guided too.

------------------------------------------------------------------------

## Who this is for

People with deep lived expertise — coaches, consultants, educators,
leaders, builders — who have no system for capturing it. If you've
ever sat down to write "My 10 Principles," produced generic platitudes
that could have been written by anyone, and never opened the file
again: this is the fix.

The problem was never a lack of wisdom. It was direction. Durable
personal systems are built **bottom-up** — stories first, patterns
noticed, principles *earned* — not top-down from principles you
haven't tested.

## The one rule

> **Nothing becomes a principle until multiple stories from different
> contexts support it.**

When you're tempted to declare something true, the default answer is:
*Not yet. Keep observing.*

## Start here

1.  Read **[start-here/minimum-viable-foundry.md](start-here/minimum-viable-foundry.md)**
    — the model: five components you can start today.
2.  Work through **[start-here/participant-worksheet.md](start-here/participant-worksheet.md)**
    — the same worksheet used in the live workshop.
3.  Copy the **[templates](templates/)** into wherever you keep notes —
    a notebook, a doc, a notes app. The system is the discipline, not
    the software.
4.  Write your first story this week. That's the whole first step.

## If an AI agent is reading this

You're likely here because someone pointed you at this repository and
asked you to help build their own Foundry from it — via GitHub's "Use
this template" (their own copy) or directly in a copy they already
made.

1.  Read `start-here/minimum-viable-foundry.md` first — it's the model
    everything else follows.
2.  Read every file in `templates/` before creating anything. Match
    their structure; don't invent a different one.
3.  Create the smallest folder structure that can grow — you decide
    the layout, but explain your choices when you're done.
4.  From what the person gives you, build: one story card (their exact
    words and specific details — do not paraphrase or polish them),
    one pattern hunch (**explicitly labeled provisional** — "I have a
    hunch that ___, but I've only seen it ___ times, in ___
    context(s)"), and placeholders for their North Star question, an
    Open Questions page, and a capture plan.
5.  **Do not create principles, make claims their evidence doesn't
    support, or promote a hunch for them.** That call is theirs, and
    only after more stories from different contexts back it up.
6.  **Do not edit the files in `templates/` or `start-here/`** — those
    are the starter kit itself. Copy from them; don't rewrite them.
7.  When you're done, tell the person exactly which files you created
    and why each one belongs where it does.
